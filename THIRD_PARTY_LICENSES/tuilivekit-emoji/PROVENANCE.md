# Third-party artwork: the room-chat emoji set

Retrieved 2026-10-27 from the `main` branch of each repository. Nothing here was
re-drawn or pixel-edited; the only changes are the filenames and the text codes we
show to users.

## What was taken

62 emoji images, shipped as
[`backend/public/emoji/*.webp`](../../backend/public/emoji) with
`manifest.json` generated by `backend/scripts/build-emoji-manifest.cjs`.

| Upstream file | Repository | Licence |
| --- | --- | --- |
| `TUIKit/TUIChat/tuichat/src/main/assets/chatbuildinemojis/emoji_0..61.webp` | [TencentCloud/chat-uikit-android](https://github.com/TencentCloud/chat-uikit-android) | Apache License 2.0 ([text](LICENSE-APACHE-2.0-chat-uikit.txt)) |

## Where it also appears upstream, and how the copies compare

The same 62 faces are published three times across the two repositories, so the
"merge both sources" question resolved to one set rather than two:

* `Tencent-RTC/TUILiveKit` → `Android/tuilivekit/src/main/res-barrage/drawable-xxhdpi/live_barrage_emoji_0..61.png`
  (MIT, [text](LICENSE-MIT-TUILiveKit.txt), Copyright (c) 2024 Tencent RTC Community)
* `TencentCloud/chat-uikit-android` → `TUIKit/TUIRoomKit/tuiroomkit/src/main/res/drawable-xxhdpi/tuiroomkit_float_chat_emoji_0..61.png`
* `TencentCloud/chat-uikit-android` → `TUIKit/TUIChat/tuichat/src/main/assets/chatbuildinemojis/emoji_0..61.webp`

Verified on the downloaded files: all 160x160 RGBA PNGs, and the TUILiveKit set and
the TUIRoomKit set are **byte-identical** (sha256 over all 62). The TUIChat `.webp`
files are the same 62 faces at the same 160x160, re-encoded as lossy WebP with
alpha — 876 KB for the set against 1.6 MB for either PNG copy.

So the WebP encoding from chat-uikit (Apache-2.0) is what ships, because it is the
same artwork at 45% of the size and both Android and the admin panel decode WebP
natively. The MIT licence text is kept alongside because the upstream attribution
for this artwork traces back to TUILiveKit.

## What was changed

* File names: `emoji_32.webp` → `poop.webp`, and so on. Every file is renamed to a
  kebab-case key chosen in this repository.
* Short codes: upstream writes `[TUIEmoji_KindSmile]` in a message body. This
  project writes `[kind-smile]`. The upstream code pattern
  `\[TUIEmoji_[a-zA-Z0-9_]+\]` appears nowhere in this repository's source, wire
  format or UI.
* Two names were replaced because the upstream label is a mistranslation or an
  in-joke that does not travel: `Shit` → `poop`, `Daemon` → `demon`.
* `manifest.json` is generated, not upstream, and carries no upstream string.

## What was deliberately not taken

* `Android/tebeautykit/**` and `Android/tceffectplayerkit/**`, including every
  `MotionRes/**/*.json|png|zip` face-mask and AR template. Those only decode inside
  Tencent's closed-source `tcmediax` binary SDK, so shipping them would mean
  shipping a Tencent runtime dependency — the opposite of this project's rule that
  the app talks to no Tencent service and links no Tencent SDK.
* Every `.kt` and `.java` file in both repositories. The emoji *behaviour* here
  (short-code pattern, span replacement, recent-emoji row) was re-implemented from
  scratch against this project's own Compose and Socket.IO stack.
* `app_tencent_cloud_logo.png`, `tcloud_logo_en.png`, `tcloud_logo_zh.png`,
  `logo.svg`, `app_ic_launcher.png` and any other mark. Trademarks are not granted by
  either licence, and this app is not a Tencent product.
* `res-gift/drawable-xxhdpi/gift_heart0..8.png`, `gift_ic_like.png`,
  `gift_function_like.png`, `gift_icon.png` — inspected and rejected on quality, not
  licence. They are 64-132 px, and the nine heart frames are 8-bit colour-mapped.
  This project's own generated gift art is 256 px RGBA
  (`backend/scripts/generate-placeholder-assets.cjs`), and the like layer draws
  vector hearts, so taking theirs would replace better art with worse.
* `gift_default_avatar.png`, `audience_list_default_avatar.png`,
  `core_default_user_icon*.png` and the like — placeholder avatars this project
  already generates itself.
